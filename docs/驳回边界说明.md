# 驳回边界说明（口径钉死，当日锁定）

- 生效日期：2026-11-17
- 选定规则：**甲规则**（二选一，已钉死；乙规则影子驳回单方案不启用，两边不得混驳）
- 锁定要求：2026-11-17 当日不提供任何变更入口，不允许改口径；后端无修改本说明的接口，`GET /api/policy` 只读返回口径与校验哈希。

## 甲规则口径（唯一口径）

驳回路径对正式切片表零更新：驳回只允许改待审队列状态与驳回原因，并回滚待审草稿（待审单置为「已驳回」，草稿永远不得再合并）。

### 驳回路径允许的写操作（白名单）

1. `UPDATE review_tickets`：仅 `status='已驳回'`、`reject_reason`、`decided_by`、`decided_at`、`version` 字段。
2. `INSERT audit_log`：登记驳回处置记录。
3. `INSERT conflict_queue`：仅在撞车争用时登记冲突。

### 驳回路径禁止的写操作（黑名单，SQLite authorizer 强制 DENY）

1. 禁止写正式切片表 `slices`（行数、完整度、放行态一律零更新）。
2. 禁止写放行流水 `releases`。
3. 禁止写消费水位 `watermarks`（驳回后不得继续推水位）。
4. 禁止任何 DDL 及白名单之外表的写操作。

### 强制与拦截

- 驳回事务在连接上安装 `install_reject_authorizer`，由 SQLite 授权回调在引擎层 DENY，不依赖代码自觉。
- 一旦出现越权写：整笔事务回滚，接口返回 403「驳回口径偏了」，并以独立连接向 `audit_log` 写入 `kind='deviation'` 偏离记录。
- 驳回不得改正式切片行数或完整度，也不得在驳回后推水位；偏离即拦下并记下「驳回口径偏了」。

### 撞车串行

- 同一待审单上驳回与确认并发时，所有处置事务以 `BEGIN IMMEDIATE` 取得库级写锁，按角色串行。
- 后手写者争用失败：返回 409，并向 `conflict_queue` 落一条争用记录；正式行只有确认入口按合并规则可改，驳回永远不改正式行。

### 互证

候审列表（`review_tickets`）、分区详情（`/api/partitions` 聚合）、冲突队列（`conflict_queue`）、策略条（`/api/policy`）、处置页（`audit_log`）五处视图同源互证，计数必须对得齐。
